Part 1 opened with a cartoon: an AI factory, every dashboard green, and an anomalies panel reading "Boardroom booked 10 times".

Six parts later, the boardroom is booked once.
Not because the model got smarter. Because of what we put around it.

One flow:
→ A person states the intent.
→ The invariants are written down, with their evidence.
→ A contract fixes "done" and the tests, before any code.
→ An agent writes code inside a harness with enforced limits.
→ Deterministic checks decide.
→ An AI reviewer may add failures, never remove them.
→ A person approves, with evidence. The default is no.

The orchestrator is plain code, not an agent. For the part whose job is to make sure the checks happen, I want boring.

A coding agent produces code.
An engineering factory produces code and the evidence that it is safe to ship.

If I started in a real team on Monday: one invariant as a test, one prompt rule moved into the system, one non-negotiable check, protected tests and pipeline, and a clear line for what needs a person.
